# Codice

> **Your source code stays on your machine.**

A browser-based developer tool that turns one or more software project folders into polished **DOCX**, **PDF**, and **ODT** documents — with syntax highlighting, line numbers, file headers, project structure trees, and a fully customizable template system.

100% client-side. No backend, no accounts, no telemetry. The only network requests are for the initial page load, Google Fonts (UI), and Shiki grammar/theme JSON (lazy-fetched, then cached).

## Features

- **Multiple project folders** — drop in several projects at once. Each is preserved as a separate section in the document with its own file tree.
- **Two output modes for multiple projects**:
  - **Combined** — all projects in one document.
  - **Separate** — one document per project, packaged into a ZIP for convenient download.
- **Configurable file detection** — sensible defaults exclude `node_modules`, `build`, `.git`, `target`, binary files, etc. Override anything via glob patterns.
- **Optional config files** — opt-in to including `build.gradle`, `package.json`, `CMakeLists.txt`, `Makefile`, `Dockerfile`, `.gitignore`, `requirements.txt`, YAML/JSON/XML configs, and more.
- **Interactive file tree** — expand/collapse folders, search files, filter by extension, toggle individual files or entire directories, override exclusions per-file.
- **Language-agnostic syntax highlighting** — powered by [Shiki](https://shiki.style/) (the same highlighter used by VS Code). Supports 8 built-in themes. Unknown languages gracefully fall back to plain text — the application does not maintain a hardcoded finite language list.
- **Three export formats**:
  - **DOCX** — primary format; code remains as selectable, editable text with colored runs.
  - **PDF** — generated by jsPDF with manual placement of colored text.
  - **ODT** — built from scratch using JSZip + OpenDocument XML.
- **Template Customizer** — a built-in style builder with live preview. Replace arbitrary template upload with a comprehensive customizer for page, typography, headings, code blocks, file headers, project headers, title page, and colors.
- **Custom presets** — save your own presets, duplicate built-ins, rename, delete, and import/export as JSON.
- **Light & dark UI themes** — proper semantic theme architecture. No more dark text on dark backgrounds. Foreground colors dynamically follow the active theme.
- **Toast notifications** — success, error, warning, and loading toasts with auto-dismiss and manual close.
- **Proper font selector** — choose from curated body and code fonts with preview, fallback stacks included.
- **Drag-and-drop** — drop folders directly onto the upload area.
- **File System Access API** — when available, the picker reads folders directly; falls back to `webkitdirectory` input otherwise.
- **Privacy-first** — no telemetry, no accounts, no server-side processing.

## How to use

1. **Add a project** — click the upload area or drag a folder onto it. The app scans the folder and displays its file tree.
2. **Select files** — toggle individual files or entire directories. Use the search box and extension filter to narrow the list. Click "Show excluded files" to override exclusions per-file.
3. **Customize the template** — click **Template** in the top-right to open the Template Customizer. Adjust page, typography, headings, code, file headers, project headers, title page, and colors. The live preview on the right updates instantly.
4. **Save a preset** — built-in presets (University, Developer, Minimal, Dark Code) are read-only. Use "Save as" to create your own custom preset. Custom presets can be renamed, deleted, duplicated, and exported/imported as JSON.
5. **Choose output mode** — when multiple projects have selected files, choose **Combined** (one document) or **Separate** (ZIP archive with one document per project).
6. **Pick a format** — DOCX, PDF, or ODT.
7. **Generate** — click **Generate**. A toast notification confirms success and the file downloads automatically.

```
      ↓

      ↓

      ↓
Syntax Highlighting   (src/lib/highlight/highlighter.ts — Shiki, lazy-loaded)
      ↓
Document Model        (src/lib/documentBuilder.ts)
      ↓
DocumentPreset        (src/lib/presets/documentPreset.ts)
      ↓
┌───────────────┬───────────────┬───────────────┐
│ DOCX Exporter │ PDF Exporter  │ ODT Exporter  │
└───────────────┴───────────────┴───────────────┘
```

### Theme architecture

The UI uses semantic CSS custom properties that swap between light and dark values:

```css
:root {
  --color-background: ...;
  --color-text-primary: ...;
  --color-surface: ...;
  /* ... etc */
}
```

Components reference these via Tailwind utility aliases (`bg-surface`, `text-primary`, etc.) — never via raw hex colors. This fixes the previous dark-theme bug where text colors were hardcoded for light mode and became invisible on dark backgrounds.

Theme tokens are defined in `src/lib/themes/uiTheme.ts`. The `applyUITheme()` function writes all variables to `document.documentElement.style` and sets `data-theme="light|dark"` on the `<html>` element.

### Document preset model

A single `DocumentPreset` (defined in `src/lib/presets/documentPreset.ts`) describes every visual aspect of a generated document:

```ts
interface DocumentPreset {
  page: PageStyle;
  typography: TypographyStyle;
  headings: HeadingStyles;     // title, h1, h2, h3, h4
  code: CodeBlockStyle;
  fileHeaders: FileHeaderStyle;
  projectHeaders: ProjectHeaderStyle;
  titlePage: TitlePageStyle;
  colors: DocumentColors;
  // ...
}
```

All three exporters consume the same preset (via `presetToOptions()` adapter for backward compatibility with the existing `DocumentOptions` shape). A style change requires touching only one place.

### Multi-project output modes

When two or more projects have selected files, the export panel exposes a **Mode** selector:

- **Combined** — builds a single `DocumentModel` with all projects and exports one file.
- **Separate** — builds one `DocumentModel` per project, runs the exporter for each, and packages the results into a ZIP using JSZip. The ZIP filename uses the configured output filename; individual files inside use each project's label.

### Toast notification system

Toasts are managed via a React context (`ToastProvider` in `src/components/common/Toast.tsx`). Success, warning, error, and loading states are supported. Auto-dismiss defaults to 5 seconds for non-loading toasts; loading toasts are sticky until explicitly dismissed or updated. The viewport caps at 4 visible toasts — older ones are dropped.

### Language-agnostic behavior

Codice does not maintain a hardcoded list of supported languages. Language detection works as follows:

1. Check special filenames (`Dockerfile`, `Makefile`, `CMakeLists.txt`, `.gitignore`, etc.)
2. Check file extension against a mapping table.
3. Fall back to `plaintext` if unknown.

The Shiki highlighter lazily loads grammars on demand. If a grammar is unavailable, the highlighter silently falls back to plaintext — the file is still importable, selectable, and exportable. Unknown languages never cause failures.

## Browser requirements

- Modern Chromium-based browser (Chrome, Edge, Brave, Arc) — recommended.
- Firefox 102+ (works without File System Access API; falls back to `webkitdirectory`).
- Safari 15.4+ (folder picker falls back to `webkitdirectory`).

## Privacy model

- **No backend.** Static SPA — no server receives your code.
- **No telemetry.** No analytics, no error reporting, no tracking.
- **No accounts.** Nothing requires login.
- **No third-party APIs** (except Google Fonts for the UI and Shiki's CDN for grammar JSON, both lazy-fetched and cached).
- **Local persistence.** Settings, custom presets, and selection state are saved to `localStorage`. Uploaded file content is never persisted.

## How to add a new language

Languages are mapped in `src/lib/languageDetection.ts`. Add an entry to `EXTENSION_MAP` or `FILENAME_MAP`. Then ensure Shiki supports the language id — most TextMate grammars are bundled. If unavailable, the file falls back to plaintext automatically.

## How to add a new exporter

1. Create `src/lib/exporters/myExporter.ts` implementing `DocumentExporter`.
2. Register it in `src/lib/exporters/index.ts`.
3. Add the format to the union type and the format selector in `ExportPanel.tsx`.

The exporter receives a fully-built `DocumentModel` — it doesn't need to know anything about file parsing or highlighting.

## How to add a new font

Add an entry to `BODY_FONTS` or `CODE_FONTS` in `src/lib/fonts/fontCatalog.ts`. Include a sensible fallback stack ending in a generic family (`sans-serif`, `serif`, or `monospace`).
