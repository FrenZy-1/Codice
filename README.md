# CodeDoc Generator

A browser-based developer tool that turns one or more software project folders into polished **DOCX**, **PDF**, and **ODT** documents containing your source code — with syntax highlighting, line numbers, file headers, project structure trees, and configurable themes.

> **Your source code stays on your machine.**
> All processing happens client-side in the browser. No backend, no accounts, no telemetry. The only network requests are for the initial page load and Google Fonts.

## Features

- **Multiple project folders** — drop in several projects at once; each is preserved as a separate section in the document with its own file tree.
- **Configurable file detection** — sensible defaults exclude `node_modules`, `build`, `.git`, `target`, binary files, etc. Override anything via glob patterns.
- **Optional config files** — opt-in to including `build.gradle`, `package.json`, `CMakeLists.txt`, `Makefile`, `Dockerfile`, `.gitignore`, `requirements.txt`, YAML/JSON/XML configs, and more.
- **Interactive file tree** — expand/collapse folders, search files, filter by extension, toggle individual files or entire directories, override exclusions per-file.
- **Syntax highlighting** — powered by [Shiki](https://shiki.style/) (the same highlighter used by VS Code). Supports 8 built-in themes (GitHub Light/Dark, One Dark Pro, Dracula, Monokai, Solarized, Nord).
- **Three export formats**:
  - **DOCX** — primary format; code remains as selectable, editable text with colored runs.
  - **PDF** — generated by jsPDF with manual placement of colored text.
  - **ODT** — built from scratch using JSZip + OpenDocument XML.
- **Live preview** — see an HTML approximation of the final document before exporting.
- **Templates & presets** — University Submission, Developer Documentation, Minimal, Landscape Wide-Code. Save your own by adjusting settings (persisted to `localStorage`).
- **Drag-and-drop** — drop folders directly onto the upload area.
- **File System Access API** — when available, the picker reads folders directly; falls back to `webkitdirectory` input otherwise.
- **Privacy-first** — no telemetry, no accounts, no server-side processing.

## How to use

1. **Add a project** — click the upload area or drag a folder onto it. The app scans the folder and displays its file tree.
2. **Select files** — toggle individual files or entire directories. Use the search box and extension filter to narrow the list. Click "Show excluded files" to override exclusions per-file.
3. **Configure the document** — click **Settings** in the top-right to choose a preset, adjust page size/margins, change the syntax theme, edit metadata, or fine-tune the filter rules.
4. **Preview** — the right pane shows a live HTML approximation of the document. Code is highlighted using the same Shiki theme that will be used in the export.
5. **Export** — choose DOCX, PDF, or ODT in the bottom bar, optionally rename the file, and click **Generate**. The file is downloaded immediately.

### Exporter abstraction

Every exporter implements:

```ts
interface DocumentExporter {
  readonly format: 'docx' | 'pdf' | 'odt';
  readonly label: string;
  readonly mimeType: string;
  readonly extension: string;
  export(model: DocumentModel, options: ExportOptions): Promise<ExportResult>;
}
```

Exporters are registered in `src/lib/exporters/index.ts` and looked up by `getExporter(format)`. They are completely decoupled from file parsing and highlighting — adding a new format (e.g. EPUB, HTML) only requires implementing the interface and registering it.

### Syntax highlighting

[Shiki](https://shiki.style/) is loaded lazily — the initial bundle stays small. The first time a language or theme is requested, Shiki fetches its grammar/theme JSON dynamically. After that, subsequent highlights are synchronous from the cache.

Shiki produces tokens with associated colors (in hex). We translate these into:

- **DOCX**: colored `TextRun` objects (one per token), with bold/italic/underline flags.
- **PDF**: `doc.setTextColor(r, g, b)` calls per token, with manual x/y placement.
- **ODT**: `<text:span>` elements with `fo:color` attribute.

Code remains **selectable text** in all three formats — no screenshots, no images.

## Browser requirements

- Modern Chromium-based browser (Chrome, Edge, Brave, Arc) — recommended.
- Firefox 102+ (works without File System Access API; falls back to `webkitdirectory`).
- Safari 15.4+ (folder picker falls back to `webkitdirectory`).

The File System Access API is used when available for a better folder picker; otherwise the app falls back to a hidden `<input webkitdirectory>` element. Folder drag-and-drop uses the `webkitGetAsEntry()` API (widely supported).

## Privacy model

- **No backend.** The app is a static SPA — there is no server to receive your code.
- **No telemetry.** No analytics, no error reporting, no tracking scripts.
- **No accounts.** Nothing requires login.
- **No third-party APIs.** The only external requests are:
  - Google Fonts (Inter + JetBrains Mono) — for the UI; the *documents themselves* use whatever font you configure (defaults to standard system fonts like Courier New so documents remain portable).
  - Shiki grammar/theme JSON — fetched once from the CDN bundled with the library, then cached.
- **Local persistence.** Your settings (presets, options, metadata, filter config) are saved to `localStorage` so reloading the page preserves them. Uploaded file *content* is never persisted.

If you need full offline operation, host the built `dist/` folder on any static web server and pre-bundle Shiki grammars (see "Offline support" below).

## How templates work

CodeDoc Generator does **not** import arbitrary `.docx` / `.odt` files as templates. That would require either a heavy server-side conversion pipeline (LibreOffice headless) or unreliable client-side template manipulation. Instead, the "template" is a **JSON-serializable `DocumentOptions` object** that controls every aspect of presentation:

- Page size, orientation, margins
- Code font, size, line height, padding, background color, border
- Heading / body fonts
- Line numbers on/off
- File headers on/off
- Page breaks between files
- Table of contents on/off
- Front matter (title page) on/off
- Project structure tree on/off
- Syntax theme
- Page header / footer text (supports `{page}` and `{pages}` placeholders)

Presets are just bundles of these options. The built-in presets (University Submission, Developer Documentation, Minimal, Landscape Wide-Code) live in `src/lib/presets/presets.ts`. To create your own preset:

1. Open **Settings**.
2. Adjust everything to your liking.
3. Your settings are auto-persisted to `localStorage` — they will be there when you reload.

To share a preset, copy the JSON from `localStorage["codedoc-generator-state-v1"]` and share it.

## How to add a new language

Languages are mapped in `src/lib/languageDetection.ts`:

```ts
const EXTENSION_MAP: Record<string, string> = {
  // Add:
  myext: 'mylanguage',
};
```

Then ensure Shiki supports the language id — most TextMate grammars are bundled. If the language is not bundled, Shiki will fall back to plaintext automatically.

## How to add a new exporter

1. Create `src/lib/exporters/myExporter.ts`:

   ```ts
   import type { DocumentExporter } from './types';

   export const myExporter: DocumentExporter = {
     format: 'myformat',
     label: 'My Format (.myf)',
     mimeType: 'application/x-my-format',
     extension: 'myf',
     async export(model, options) {
       // Build your bytes…
       return {
         blob: new Blob([bytes], { type: this.mimeType }),
         filename: `${options.filename}.${this.extension}`,
         format: 'myformat',
         elapsedMs: 0,
       };
     },
   };
   ```

2. Register it in `src/lib/exporters/index.ts`:

   ```ts
   export const EXPORTERS = {
     docx: docxExporter,
     pdf: pdfExporter,
     odt: odtExporter,
     myformat: myExporter,
   };
   ```

3. Add `'myformat'` to the `outputFormat` union in `src/types/index.ts` and the format selector in `src/components/ExportPanel.tsx`.

The exporter receives a fully-built `DocumentModel` — it doesn't need to know anything about file parsing or highlighting.

## How to add a new formatting preset

Add an entry to `BUILT_IN_PRESETS` in `src/lib/presets/presets.ts`:

```ts
{
  id: 'my-preset',
  label: 'My Preset',
  description: 'Description shown in the UI.',
  builtIn: true,
  syntaxTheme: 'github-light',
  options: {
    pageSize: 'A4',
    // … any DocumentOptions fields
  },
  metadata: {
    title: 'My Default Title',
  },
}
```

## Known limitations

- **PDF text wrapping** is approximate. jsPDF doesn't natively support rich-text wrapping inside a colored run; very long tokens may overflow horizontally when "Wrap long lines" is off. Use the Landscape Wide-Code preset for projects with long lines.
- **TOC in DOCX** is a static fallback. The exporter emits both a Word `TableOfContents` field (which Word will populate when the user right-clicks → Update Field) and a static text approximation for viewers that don't update fields.
- **Web Workers** are not yet wired up for highlighting. The current implementation runs highlighting on the main thread; for projects with thousands of files, this can cause UI jank during export. The architecture is designed to allow moving `buildDocumentModel` into a worker — see "Roadmap" below.
- **Templates** are JSON-based only (see "How templates work" above). Arbitrary `.docx` template upload is intentionally not supported.
- **Shiki language loading** is lazy but synchronous-ish on first use — the first file of each new language incurs a ~50–200 ms fetch delay.
- **No PWA / offline cache** yet — the app requires an initial network load. See Roadmap.
